# Готовые демо

После сборки CMake выберите демо в списке над командой в TUI. Выбор только заполняет команду: размер и число повторений можно изменить вручную. CPU и sample сохраняются.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 2
python3 -m tui --demo matrix-rows --sample 3
```

## Команды для поля TUI

Из корня репозитория:

| Демо | Команда |
| --- | --- |
| Массив подряд | `./build/demo_array 32 8 sequential` |
| Массив с шагом 64 элемента | `./build/demo_array 32 8 strided` |
| Бинарный поиск | `./build/demo_binary_search 1048576 200000` |
| Умножение матриц по строкам | `./build/demo_matrix 256 3 rows` |
| Умножение матриц по столбцам | `./build/demo_matrix 256 3 columns` |

Можно выбрать демо при запуске TUI: `--demo array-sequential`, `--demo array-strided`, `--demo binary-search`, `--demo matrix-rows` или `--demo matrix-columns`. Старый флаг `--demo` без имени продолжает открывать прежний `demo_target`.

## Массив

```text
demo_array [size_MB=32] [passes=8] [sequential|strided]
```

`size_MB` задаётся в МиБ (1024 × 1024 байт), элементы — `uint64_t`. Последовательный вариант читает массив слева направо. Вариант с большим шагом сначала читает элементы 0, 64, 128 и далее, затем 1, 65, 129 и так далее. Оба обходят весь массив по одному разу за проход.

Параметры: размер 1–512 МиБ, проходы 1–10000. Один элемент меняется между проходами, чтобы повторения зависели от новых входных данных. При одинаковых размере и числе проходов оба порядка дают одинаковый checksum.

## Бинарный поиск

```text
demo_binary_search [elements=1048576] [queries=200000]
```

Создаётся отсортированный массив чётных чисел. Программа выполняет запросы с фиксированным seed=42, часть значений находится, часть отсутствует. В stdout выводятся число найденных значений `hits` и checksum найденных индексов. Между одинаковыми запусками результат воспроизводится.

Параметры: 1–67108864 элементов и 1–100000000 запросов. Это именно поиск в памяти, не работа с файлами.

## Умножение матриц

```text
demo_matrix [size=256] [passes=3] [rows|columns]
```

Оба варианта вычисляют произведение `C = A × B` для квадратных целочисленных матриц, хранящихся по строкам:

- `rows`: порядок циклов `i → k → j`. Внутренний цикл читает строку B и обновляет строку C.
- `columns`: порядок `i → j → k`. Внутренний цикл читает столбец B с шагом в длину строки.

Параметры: сторона матрицы 1–1024 и число умножений 1–100. В начале каждого прохода C обнуляется, один элемент A меняется одинаково в обоих вариантах. При одинаковых параметрах итоговые checksum совпадают.

Для более крупной задачи можно поставить, например, `512 3 rows` или `512 3 columns`. При необходимости увеличьте таймаут TUI через `--timeout 30`.

## Как читать результаты

`passes` — число проходов или умножений внутри одного процесса. `sample` — число отдельных запусков этого процесса из TUI. Для бинарного поиска объём работы задаёт `queries`.

Runner измеряет весь запуск: выделение и инициализацию памяти, алгоритм, вычисление checksum и вывод. Изменение времени может зависеть от кешей, векторизации и других особенностей CPU и компилятора. Конкретное ускорение не обещается.

Каждое демо запускается отдельно. Автоматического A/B-сравнения нет. Если PMU недоступен, время и ресурсные показатели видны, а аппаратные метрики остаются недоступными.

У каждого бинарника есть `--help`. Контрольные суммы и число найденных значений проверяются тестом `demos_correctness`: для поиска используется Python bisect, для матриц — независимое вычисление произведения на небольших входах.
