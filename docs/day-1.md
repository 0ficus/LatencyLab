## Результат

Собрана библиотека `latency_metrics` и тест `metrics_probe` для самостоятельной
проверки счётчиков на Linux. Код компилируется GCC 11.4 в Release, обе проверки
CTest пройдены. Есть API для передачи модуля в runner и диагностический JSON.

## Что проверено на машине

- CPU: Intel Core i5-1340P, 16 логических CPU.
- Kernel: 6.8.0-138-generic, Ubuntu.
- PMU в sysfs: `cpu_core` (CPU 0–7), `cpu_atom` (CPU 8–15).
- `perf_event_paranoid=4`, обычный пользователь без effective capabilities.
- Вне песочницы seccomp выключен; `perf_event_open` всё равно возвращает
  `EACCES` (errno 13) для cycles, instructions, cache misses и task-clock.
- Внутри песочницы результат доступа тот же.
- Утилита `perf` не найдена в PATH. Она не требуется для собственного syscall.
- Разовый sudo недоступен без интерактивного пароля пользователя.

Системный вызов существует и отвечает ошибкой доступа; аппаратные события
на этой машине пока не подтверждены успешным открытием/чтением.
Присутствие PMU и CPU-флагов не доказывает поддержку каждого события.

Чтобы закрыть аппаратную часть, пользователь из корня репозитория выполняет:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 2
ctest --test-dir build --output-on-failure
sudo ./build/metrics_probe --cpu 0 --iterations 20000000 --require-hardware > results/2026-11-10-privileged.json
```

Затем проверяет код возврата и JSON результата. При сохранении отказа нужна
машина/настройка с разрешённым perf; менять глобальный sysctl для всех
пользователей автоматически не требуется. После доступа нужно отдельно
проверить положительные cycles/instructions, время работы событий и повторить
замер с большей нагрузкой. Сопоставление с perf stat остаётся задачей дня 4.
